## 结论

1. **不是供料饿死**：卡死瞬间 vififo 只有 421 字节（已弹空），esparser 上游一路跟得上；重建后 vififo 反而堆到 700KB 说明用户态在猛灌，硬件不取。
2. **不是 DPB/buffer 管理问题**：q 从 3 涨到 17 表示驱动侧仍在正常排队；重建把 buffer 全换新（seq 归 0、q=8）后仍是 0 帧完成。
3. **不是中断全灭**：重建后 irq 仍以 +0/+1 递增（st=1），说明只有少数非"帧完成"中断在来，`IrqOnDecodeDone` 类完成中断彻底不来了。
4. wptr 在 start..end 环内继续前进、streamctl=1eb14009 使能位正常、status=00000005 与健康期一致 → **寄存器层面看不出错误，是 VDEC 硬件/固件在某一帧进入 hang（不再上报完成），驱动无能为力**。

即：卡死点在 VDEC 固件内部（单帧处 hang），streamoff/streamon 级别的软复位救不回来。要恢复只能做上层的全块复位（时钟/电源 gate 复位或模块 reload）。

## 硬复位（AO 真掉电再上电）—— 2026-11-17 落地

需求：卡死后 close+open（streamoff/streamon）救不回来，`vdec_poweroff()` 只关时钟，
硬件/固件状态原样保留。要真正复位必须翻 AO 的 `GEN_PWR_SLEEP0/ISO0`。

用法（无活动会话时）：
```sh
sh /root/vdec-reset.sh          # = echo 1 > /sys/module/meson_vdec/parameters/hard_reset
```
模块：`/root/vdec-hr5.ko`（源码 meson-vdec/vdec.c，`vdec_hr_run()`）。
流程：dos/dos_parser/vdec_hevc 时钟 → 上电 + `DOS_SW_RESET3`/`GCLK_EN3`/`MEM_PD_HEVC`/ISO 清 →
隔离 + `MEM_PD_HEVC=0xffffffff` + `SLEEP0` 掉电 → 再上电。搞完留在「刚上电、未装固件」的干净状态。

### 踩的坑（很重要）
1. **无会话时写 `HEVC_ASSIST_MBOX1_MASK` / `HEVC_MPSR` 会把 AXI 锁死**：整机当场硬挂，
   无 oops、无 pstore、netconsole 也不出字，只能靠硬看门狗拉回来（实测两次，每次 ~14s 后自动重启）。
   所以硬复位里**绝不能**去「停固件」，掉电已经清干净，MPSR 交给下个会话的 `__vdec_hevc_start`。
2. 挂死无日志时不要指望 printk：console 会走延迟刷写，CPU 卡在 MMIO 里那些行全丢。
   定位靠 `hard_reset` 参数的分步模式（2..6）二分：每步单独 echo 一次，看机器活不活。
3. 反过来，先上电再写 DOS 寄存器是对的：上一会话已把整块掉电+隔离，直接写会挂。

验证：硬复位后 `playtest.sh` 4K 3840x1600 → 496/496、376/376、304/304 AUs，resets=0，21~23.9fps。
