# 范围定义（已定稿 2026-11-10）

> **一句话**：驱动架构与驱动代码直接复用 Linux；其余全部对照 Linux 语义做"更简洁的等价实现"。
> 目标机器只有一台 → 多架构、通用性、可选特性全部砍掉。

## 本机形态（决定能砍什么）

```
架构 x86_64 · 6 CPU · 单 socket · NUMA 节点 1 个 · 无热插拔需求
```

单 NUMA 节点是关键：NUMA 亲和、节点间平衡、内存热插拔——整套可以删。

| 项 | 值 |
|---|---|

## 三层分类法（每个接口项都要归类）

### A 类：必须一致（ABI，一个字都不能改）

| 项 | 依据 |
|---|---|
| 导出符号的**完整类型签名** | CRC 由签名算，差个 typedef 就 `insmod` 拒绝 |
| 驱动**直接解引用**的 struct 字段偏移 | blob 预编译，偏移烧死（108 MB 不可重编译 .o） |
| 锁与睡眠语义 | `spinlock` 不可睡眠、`GFP_ATOMIC` 不可分配、`mutex` 必须真睡 |
| 返回值/errno 约定 | 驱动逐处判 `-ENOMEM`/`-EAGAIN` |
| 地址空间模型 | `ioremap`/`kmap`/DMA 一致性 |

### B 类：语义等价、实现随便换（**我们真正的工作量**）

| 子系统 | Linux 规模 | 我们可做的简化 |
|---|---|---|
| 调度器 | 6.4 万行，per-CPU CFS + 负载均衡 | 单全局运行队列 + 全局锁；保留抢占点 |
| RCU | tree RCU，多级 | **TinyRCU 式**：到静默点就停住全 CPU |
| 分配器 | SLUB + per-CPU 缓存 + 迁移类型 | buddy + 简单 slab；kmalloc 尺寸类别保持一致 |
| 页回收 | LRU 多链表 + cgroup + zswap | 单 LRU + 直接回收，不做 swap |
| 内核态 per-CPU | 动态分配 + 热插拔 | 静态数组，无热插拔 |
| VFS | 1488 文件 / 147.6 万行 | 只留需要的那几个文件系统 |
| blk 层 | 6.7 万行，blk-mq 全套 | bio 直通起步，blk-mq 后补 |
| 模块加载 | 签名 + 强制校验 + 多级 | **保留**：vermagic + `__versions` CRC + 重定位；**去掉签名** |

### C 类：直接砍掉

多架构（除 x86-64）· ia32/32 位兼容 · cgroup · namespace/容器 · KVM/Xen/Hyper-V ·
BPF/perf/ftrace/kprobes · audit/SELinux/AppArmor · suspend/hibernate · CPU/内存热插拔 ·
NUMA · 绝大多数文件系统 · 密码学算法集 · 网络协议族（先只留 IPv4）· 驱动（除本机 7 类）

## 一个关键区分：blob vs 可重编译驱动

这条区分决定了 A 类的范围：

| | 约束强度 | 原因 |
|---|---|---|
| **nvidia blob**（108 MB 预编译 `.o`） | **强制**：布局/CRC 必须是 Linux 7.2.12 | 不可重编译 |
| **复用的驱动源码**（pci/nvme/ata/usb/xhci/r8169/snd） | **可选**：能用我们自己的布局 | 会跟着我们的头文件重编 |

但结论仍然是**全局按 Linux 布局走**：驱动集的 include 闭包是

```
386 个内核头文件（linux/ 331 · asm/ 44 · net/ 11），一层就 ≥ 161,547 行
```

偏离 Linux 哪怕一处，这 16 万行的自洽性就要自己维护——省下的自由不值这个代价。

## 真正的规模账（估计，非实测）

| 部分 | 来源 | 估计 |
|---|---|---|
| 驱动层（架构 + 本机 7 类 + drm 核心） | 移植/shim，非重写 | 5~8 万行 |
| ABI 头文件基线 | 386 个头的裁切版 | ~8 万行 |
| 我们自己的内核（mm/sched/vfs/blk/arch） | 简化实现 | 2~4 万行 |
| **合计** | | **~15~20 万行**，对比 Linux 3721 万行 |

**压缩比 ~200:1**，代价是只跑这一台机器。
