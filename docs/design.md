# 分块重写方案（design.md）

> **一句话**：驱动层原样复用 Linux，内核**实现层**按块替换成自己的简化实现；
> 每块都必须能在 `drivers/` 全部源码驱动 + nvidia blob 照常工作的前提下独立换掉。

本篇是 `docs/scope.md`（范围定义）的**落地路径**。scope.md 回答"要做什么、不要做什么"，
本篇回答"**按什么顺序、用什么机制、怎么验收**"。

**路线变更说明**：此前讨论过的"全自研 L0 内核（M1 = QEMU 启动最小内核）"**暂停**。
理由：那条路要求从零重建 610 个导出符号 + 1910 个头文件的布局契约，等于重写 Linux 的
契约面本身；而分块重写可以**复用现成契约、只换实现**，风险差一个数量级。

## 1. 三条冻结线（实测，不是估计）

在裁剪后的树上跑出来的数字：

| 冻结线 | 规模 | 为什么冻 |
|---|---|---|
| **驱动源码** | `drivers/` 10,959 个 `.c` / **793.5 万行** | 不写，直接用 Linux 的（已确认的决策） |
| **驱动可见头文件** | **1,910 个** `<linux/*.h>` / 26.8 万行（仅直接 include，不含闭包） | 驱动直接解引用 `task_struct`/`page`/`file`/`inode` 的字段，偏移一改全盘编译失败 |
| **导出符号签名** | 24,327 个导出符号，其中 **610 个** 被 nvidia blob 硬依赖 | CRC 由签名算，差一个 typedef 就 `insmod` 拒绝 |

三条线合起来是一句话：**结构体布局和导出签名只能跟着 Linux 走，实现层随便换。**

裁剪后全树（对照用）：

```
16,645 个 .c  →  1,262.8 万行
 6,671 个 .h  →  259.9 万行；其中 include/ 1,461,535 行
```

## 2. 账本：哪些行永远不写

| 层 | 行数 | 处置 |
|---|---|---|
| `drivers/` | 7,934,538 | **不写**（原样编译） |
| `include/`（驱动可见部分） | 约 267,790 | **锁死**（布局契约） |
| `fs/` | 1,275,459 | 主体不碰，只删不用的 fs |
| `net/` | 1,242,466 | **不碰**（TCP/IP 栈不在射程内） |
| `kernel/` | 527,512 | 部分替换（sched / rcu / locking / time） |
| `arch/x86/` | 342,458 | 入口、页表格式不动；`arch/x86/mm` 的边缘可换 |
| `mm/` | 215,364 | 只换分配器，**VM 主体（mmap/fault/reclaim）不碰** |
| `lib/` `block/` `crypto/` `security/` `ipc/` | 合计 ~50,000 | 边缘 |

**可写区 = 3~5 万行。** 相对 1,262.8 万行是 **0.3%**；
相对 Linux 上游 3,721 万行是 **0.1%**（scope.md 记的 ~200:1 压缩比就是这笔账）。

这个比例不是缺陷——**内核里真正属于"策略"的部分本来就只有这么多**，
剩下全是"把硬件和契约伺候好"的工程量。

## 3. 分块清单

判定标准只有一条：**契约面是不是头文件？**
契约面全是头文件（= 冻结线内）的块优先；有任何一处要改进程 ABI 或结构体布局的块，押后。

| # | 块 | Linux 行数 | 目标 | 工期 | 风险 | 顺序 |
|---|---|---|---|---|---|---|
| 1 | **RCU** | 16,814 | ~500（TinyRCU 式：到静默点停全 CPU） | 1 周 | 低 | **第一刀** |
| 2 | **locking** | 18,661 | 1~2 K（mutex/spinlock/rwsem 语义严格照抄） | 2~3 周 | 中 | 第二 |
| 3 | **timer / workqueue / 软中断** | 与 kernel/ 混杂 | 3~4 K | 2~3 周 | 中 | 第三 |
| 4 | **mm 分配器**（buddy + slab） | mm/ 的一部分 | 3~5 K，kmalloc 尺寸类别保持不变 | 1~2 月 | 中 | 第四 |
| 5 | **sched** | 64,666 | 5~8 K（单全局运行队列 + 全局锁，保留抢占点） | 1~2 月 | 中高 | 第五 |
| 6 | **blk 层** | ~5,500（blk-mq 另有规模） | bio 直通起步，blk-mq 后补 | 1~2 月 | 中 | 第六 |
| 7 | **模块加载器**（保留而非重写） | — | vermagic + `__versions` CRC + 重定位，**去签名** | 2 周 | 中 | 并行 |

**明确不做**（写进红线的部分见 §7）：VFS 主体、net 栈、mm 的 VM 主体（mmap/page fault/reclaim）、
DRM（461,364 行，nvidia 直接绑死）、任何 `uapi/`。

### 为什么 RCU 是第一刀

1. **契约面干净**：对外只有 `rcu_read_lock`/`synchronize_rcu`/`call_rcu` 等十来个函数，全在头文件里。
2. **规模合适**：Linux 16,814 行 → 我们 ~500 行，一周能收口。
3. **坏状立现**：写错了立刻 panic 或挂死，不存在"悄悄退化"。
4. **不依赖 sched/mm**：反过来 sched 依赖 RCU，先做 RCU 才不返工。
5. **完整往返最有说服力**：一个月内跑完"自研代码在真内核里服役"的闭环，
   比任何设计文档都更能证明这条路可行。

## 4. 替换机制（关键设计）

**不要一次性切到自研内核。** 采用"双实现并存 + 一次只换一块 + 随时回退"：

```
                    ┌─ 契约面（头文件，冻结）────────────────┐
调用方（drivers/ 等）│  rcu_read_lock() / kmalloc() / ...     │
                    └────────────┬───────────────────────────┘
                                 │ 编译期选择
                    ┌────────────┴────────────┐
                    │ CONFIG_MK_RCU=y         │  ← 每块一个开关
              ┌─────┴─────┐             ┌─────┴─────┐
              │ Linux 实现 │             │ 自研实现  │
              │ (默认，稳) │             │ (候选)    │
              └───────────┘             └───────────┘
```

规则：

1. **头文件不动**。自研实现必须落在与 Linux 同名同签名的函数背后，`drivers/` 一行不用改。
2. **一块一个 Kconfig 符号**（`CONFIG_MK_RCU`、`CONFIG_MK_SCHED`…），默认关 = 用 Linux 原版。
3. **同一时刻只开一个 `CONFIG_MK_*`**。两个自研块同时上，出问题无法定位。
4. **每次替换都必须能编译出完整 bzImage 并装上真机**。不能"先改造三个月再试启动"。
5. **回退成本 = 翻一个开关 + 重编**（增量构建，见 `docs/build.md`）。

### 落地形态

```
src/linux-7.2.12/              裁剪后的树（工作面）
  kernel/rcu/                  Linux 原版（保留，不动）
  mk/                          ★ 自研实现，新目录，不进 include/
    rcu/rcu.c                  CONFIG_MK_RCU=y 时编入，符号与 kernel/rcu 同名
    locking/…
    sched/…
    mm/…
  mk/Kconfig.mk                ★ 一个文件收全部 MK_* 开关
```

`mk/` 是唯一新增目录，**永远不改上游文件内容**——这样 `src-archive/` 快照、
上游 diff、裁剪阶段的"一字没改"原则全部继续有效。

## 5. 每块的契约清单模板

换任何一块，先填这张表，填不满就不许动手：

| 项 | 内容 |
|---|---|
| **契约函数** | 块对外暴露的全部函数/宏，逐个列出签名 |
| **符号可见性** | 是否 `EXPORT_SYMBOL`？被 nvidia 610 条里的哪几条依赖？ |
| **结构体** | 涉及哪些冻结结构体（`task_struct`/`page`/`spinlock_t`…）的哪些字段 |
| **必须保持的语义** | 例：`spinlock` 不可睡眠、`GFP_ATOMIC` 不可阻塞、`mutex` 必须真睡、`rcu_read_lock` 不可阻塞 |
| **允许删掉的** | 例：NUMA 亲和、热插拔、cgroup 感知、per-CPU 动态分配 |
| **验收用例** | 具体命令 + 期望输出，见 §6 |

以 RCU 为样板：

| 项 | RCU |
|---|---|
| 契约函数 | `rcu_read_lock/unlock`、`rcu_dereference`、`synchronize_rcu`、`call_rcu`、`rcu_barrier` |
| nvidia 依赖 | 610 条中不直接出现（经 `drm_atomic`/`dma_fence` 间接触发） |
| 涉及结构体 | `task_struct` 4 个 PREEMPT_RCU 字段（`rcu_read_lock_nesting`/`rcu_read_unlock_special`/`rcu_node_entry`/`rcu_blocked_node`，`include/linux/sched.h:940-943`）+ tasks 系列 5 个 `rcu_tasks_*`；**布局不动**，但语义由自研实现自持（`rcu_preempt_depth()` 宏的正确性据此） |
| 必须保持 | `synchronize_rcu` 返回后所有旧读者已离开临界区；`rcu_read_lock` 内不可睡眠 |
| 可删 | tree 层级、`CONFIG_RCU_NOCB`、`RCU_LAZY`、expedited 变体、stall 检测、rcutorture/rcuscale/refscale 全套；SRCU 不在本块射程 |
| 验收 | 启动到桌面；`CONFIG_MK_RCU=y` 下 24h 不挂；blob 正常加载 |

> 展开版（实测数据、141 条导出符号、本机 config 冲突、7 步验收、6 条风险）：`notes/mk-rcu.md`。

## 6. 验证体系

四层，缺一不可：

| 层 | 手段 | 判据 |
|---|---|---|
| **编译期** | `tools/abi/check_symvers.py`（零编译 CRC 对表） | 610 条 nvidia 符号 CRC 不变 |
| **启动期** | `tools/trim/verify-boot.sh`（QEMU 真启动 + ext4 挂载断言） | 到 shell、挂载成功、无 oops |
| **运行时** | 真机装机 + nvidia 模块加载 + 桌面起来 | `dmesg` 无 WARN、无 hung task |
| **等价性** | 同一 workload 下 Linux 版 vs 自研版对比 | 行为一致；性能允许退化，**不允许超过 2~3 倍** |

另外每条都必须测的**回退验证**：把 `CONFIG_MK_*` 关掉重编，确认能回到全 Linux 实现并正常启动。
回不去的块，视为没做完。

## 7. 红线

1. **不改 `drivers/`**，一行都不改。
2. **不改 `include/` 里驱动可见的结构体布局**，字段顺序/类型/偏移冻结。
3. **不改任何 `uapi/`**（用户态 ABI 是桌面和 nvidia 的共同地基）。
4. **不动 VFS 主体和 net 栈**（耦合中心，动了等于重写驱动）。
5. **不动 mm 的 VM 主体**（mmap/page fault/reclaim 与 DRM GEM 深度耦合）。
6. **不碰 DRM**（461,364 行，nvidia blob 直接绑定）。
7. **不追求通用性**：这台机器能跑就是全部目标，不为其他硬件留抽象层。

## 9. 工期与人力预期

| 阶段 | 块 | 累计 |
|---|---|---|
| M1~M2 | 骨架 + RCU | 2~3 周 |
| M3~M4 | locking + timer/workqueue | +5~6 周 |
| M5~M6 | mm 分配器 + sched | +3~4 月 |
| M7 | blk + 模块加载 | +2 月 |

**总计 6~12 个月**（单人 + AI 辅助，按每块都要真机验证的前提下）。

对比参考：裁剪阶段五轮全新构建从 20m05s 压到 7m53s，编译单元 9,000 → 4,584——
那个阶段的账是**可复现的实测**；本表工期是**估计**，每完成一块要回来修正。
